# 코드 패턴 · 원칙 점검 · 메모리(스택/큐/힙) 점검

> 이 문서는 **점검 기록**입니다. 코드를 고치라는 뜻이 아니라 "지금 코드가 어떤 패턴을 쓰고, 어디가 좋고, 어디가 아쉬운지" 를 남겨 둔 것입니다.
> 기준 시점: 2026-10-16 (Assets/cs 25개 파일)

## 1. 사용한 디자인 패턴
| 패턴 | 어디서 | 설명 |
|---|---|---|
| **싱글톤 (Singleton)** | `GameManager.Instance`, `SoundManager.instance`, `ButtonManager.instance` | 게임 전체에 하나만 있는 매니저. 어디서든 바로 접근 |
| **옵저버 (Observer)** — C# 이벤트 | `Ball.Thrown/OutOfBounds`, `BallSpawner.BallThrown`, `GameManager.ScoreChanged`, `ButtonManager.NextLevelClicked/StartGameClicked/GameExiting`, `SoundManager.SongChanged` | 알리는 쪽은 듣는 쪽을 모름 |
| **옵저버 — UnityEvent** | `LevelClearUI`, `PauseMenuUI` | Inspector 에서 연결 → 프리팹을 다른 게임에서 재사용 |
| **템플릿 메서드 + 제네릭** | `Spawner<T>` → `PinSpawner`, `BallSpawner` | 공통 순서(고르기·만들기)는 부모, `Spawn()` 내용만 자식 |
| **오브젝트 풀 (Object Pool)** | `BallSpawner` 의 `Dictionary<Ball, Queue<Ball>>` | 공을 지우지 않고 꺼서 재사용 |
| **전략 (Strategy) — 인터페이스** | `ITextPopEffect` (EffectPop), `IFloatingBehavior` (CountUpBehavior) | 효과 종류를 바꿔 끼울 수 있음 |
| **데코레이터식 체이닝** | `EffectNumFlying` 의 `.With(...).With(...)` | 떠오르는 숫자에 동작을 하나씩 덧붙임 (외부 에셋 방식) |
| **레지스트리 (등록부)** | `Pin.allPins` (static List) | 켜질 때 등록, 꺼질 때 제거 → 모든 핀을 한 번에 세기/세우기 |
| **퍼사드 (Facade)** | `SoundManager` | AudioSource 3개를 감추고 `PlaySFX`, `PlaySong`, `ToggleBGM` 만 노출 |
| **중재자 (Mediator) 비슷** | `ButtonManager` | UI 버튼 ↔ LevelManager 사이에서 연결 |
| **상태 (State) — 플래그 방식** | `LevelManager` 의 `gameStarted / isJudging / isLevelOver / lastWasFail` | 상태 패턴을 클래스로 나누지 않고 bool 로 관리 |
| **코루틴 시퀀스** | `LevelManager.JudgeThrow`, `ButtonManager.Popup`, 효과들 | "기다렸다가 → 다음" 흐름을 한 함수에 순서대로 |
| **빌더 (에디터 도구)** | `OptionUIBuilder`, `PinLayoutTool`, `FontChanger` | 메뉴 한 번으로 UI/배치 생성 + Undo |

## 2. SOLID 원칙 점검
| 원칙 | 판정 | 지킨 곳 | 아쉬운 곳 |
|---|---|---|---|
| **S** 단일 책임 | △ | `Ranking`(저장) / `RankingBoard`(그리기), `Ball` / `BallSpawner`, 효과 스크립트 하나에 효과 하나 | **`ButtonManager`** 가 레벨 글자·팝업·판넬·랭킹·멈춤·시작 버튼을 혼자 함. **`LevelManager`** 가 레벨 진행 + 투구 판정 + 저장 + 핀/공 보이기. **`Pin`** 이 고정/풀림 + 쓰러짐 판정 + 전체 명단 관리. **`SoundManager`** 가 BGM + 노래 목록 + 효과음 |
| **O** 개방-폐쇄 | △ | `Spawner<T>`: 새 스포너는 상속으로 추가, 부모 수정 없음 | 투구 결과(MISS/GREAT/GORGEOUS…)가 `if / else if` 사슬 → 새 결과를 넣으려면 `LevelManager` 를 고쳐야 함 (결과 표(데이터)로 빼면 고치지 않고 추가 가능) |
| **L** 리스코프 치환 | ○ | `PinSpawner`, `BallSpawner` 모두 `ISpawner` / `Spawner<T>` 자리에 그대로 들어감 | — |
| **I** 인터페이스 분리 | ○ | `ISpawner`, `IReset`, `ITextPopEffect` 모두 함수 1개짜리 작은 약속 | `IReset.Reset()` 이 Unity 특수 함수 `Reset` 과 이름이 같음 (에디터 ⋮ → Reset 누르면 불림) |
| **D** 의존 역전 | ✕ | `GameManager` 가 점수 효과를 `ITextPopEffect` 로만 앎 | 상위 로직(`LevelManager`)이 구체 클래스 싱글톤(`ButtonManager`, `GameManager`, `SoundManager`)과 static(`Pin`)을 **직접** 부름. `Pin` 도 `GameManager`, `SoundManager` 를 직접 부름 |

## 3. 그 밖의 규칙
| 규칙 | 판정 | 내용 |
|---|---|---|
| **DRY** (같은 코드 반복 금지) | △ | 좋음: 파티클 생성은 `EffectPanelOpen.SpawnEffect` 하나를 버튼 효과도 같이 씀, 프리팹 저장 함수 공유. 아쉬움: 아래 4번 표 |
| **KISS** (단순하게) | ○ | 한 함수가 짧고 주석이 많음. 판정 규칙이 한 코루틴에 위→아래로 읽힘 |
| **YAGNI** (안 쓸 기능 만들지 않기) | ○ | 안 쓰는 파일(GameRestter, 고양이 도구 등)은 정리함 |
| **캡슐화** | △ | 대부분 `[SerializeField] private`. 하지만 `SoundManager` 칸들과 `Pin.isFallen` 은 `public` 필드라 누구나 바꿀 수 있음 |
| **이벤트 해제 (구독했으면 해제)** | ○ | `LevelManager.OnDestroy`, `SongListUI.OnDestroy`, `Ball.OnDisable` 에서 해제 |

> 질문 주신 "SDY ORD, SID RESULT 패턴" 은 정확히 어떤 원칙인지 확인이 필요합니다. 이름을 알려 주시면 그 기준으로도 점검해 추가하겠습니다.

## 4. 인터페이스·공통 부모가 없어서 반복된 코드 (아쉬운 점)
| 반복 | 어디 | 묶는다면 |
|---|---|---|
| 효과 설정 칸 `effectPrefab / effectScale / forwardOffset / useMotion` 이 똑같이 두 번 | `EffectPanelOpen`, `EffectButtonPress` | 공통 부모 `UIEffectBase` 또는 `IUIEffect` |
| "버튼이 눌렸다고 UnityEvent 로 알리기만" 하는 구조 | `LevelClearUI`, `PauseMenuUI` | 공통 부모 `UIEventRelay` |
| 팝업 글자의 "크게 → 원래 크기" 효과를 ButtonManager 가 **직접** 다시 구현 | `ButtonManager.Popup` vs `EffectPop` | `EffectPop` 이 색까지 바꿔 페이드와 충돌해서 따로 씀 → `ITextPopEffect` 에 "색은 건드리지 않는 효과" 를 하나 더 만들면 재사용 가능 |
| "자식 Renderer 들을 감싸는 크기(Bounds) 구하기" 가 세 번 | `Pin`(reach), `PinSpawner.GetBounds`, `Editor/PinLayoutTool` | 공용 정적 함수 `BoundsUtil.Of(GameObject)` |
| 소리 꺼내기 `sm != null ? sm.missClip : null` 5번 | `LevelManager.JudgeThrow` | 결과 표(문구 + 소리 + 보너스)로 묶으면 한 줄 |
| 글자 켜고 끄기 함수 두 개 | `ButtonManager.SetPlayUIVisible`, `SetLevelAndScoreTextVisible` | 비슷한 일 — 하나로 합칠 수 있음 |
| 리셋 이름 | `IReset.Reset()`, `Pin.ResetPin()`, `Pin.ResetAllPins()`, `LevelManager.Reset()` | `IReset` 으로 통일 가능 (Pin 도 IReset 을 지키게) |

## 5. 메모리 점검 — 스택 / 큐 / 힙

### 스택 (Stack — 함수 호출이 쌓이는 곳)
| 항목 | 판정 | 설명 |
|---|---|---|
| 재귀 호출 | ✅ 없음 | 스택 넘침(StackOverflow) 위험 없음 |
| `JudgeThrow` 가 끝에서 자기를 다시 시작 | ✅ 안전 | 코루틴을 **새로 시작**하는 것이라 호출이 쌓이지 않음 |
| 이벤트 연쇄 | ✅ 얕음 | Pin → GameManager → LevelManager 정도 (2~3단계) |
| `Bounds`, `Vector3` 등 struct | ✅ | 스택에서 쓰고 사라짐 (힙 부담 없음) |

### 큐 (Queue)
| 항목 | 판정 | 설명 |
|---|---|---|
| 공 창고 `Queue<Ball>` | ✅ | 먼저 넣은 공부터 꺼내 씀. 창고 크기 = 동시에 나와 있던 최대 공 수 → 끝없이 커지지 않음 |
| 창고가 줄지 않음 | ⚠ 작음 | 한 번 늘어난 공은 씬이 끝날 때까지 보관 (보통 5~10개라 문제 없음) |
| `pendingThrows` (밀린 투구 수) | ✅ | 숫자 하나로 셈 (실제 큐 아님), 레벨 시작 때 0 |

### 힙 (Heap — `new` 로 만든 것, 가비지 컬렉션(GC) 대상)
VR(Quest)은 GC 가 돌 때 프레임이 잠깐 끊길 수 있어 **매 프레임 new** 를 줄이는 게 중요합니다.

| 위치 | 얼마나 자주 | 판정 | 설명 |
|---|---|---|---|
| **`Pin.FixedUpdate` → `Physics.OverlapSphere`** | 고정된 핀마다 **매 물리 프레임** (핀 10개 × 초당 50~90번) | ⚠ **가장 큼** | 매번 새 배열을 만듦 → GC 쓰레기가 계속 쌓임. `OverlapSphereNonAlloc` + 미리 만든 배열이면 0 |
| `Pin.FixedUpdate` → `GetComponentInChildren<Renderer>()` | 매 물리 프레임 | ⚠ 작음 | 할당은 없지만 매번 찾는 비용 → Awake 에서 한 번 찾아 두면 됨 |
| `new WaitForSeconds(...)` | 판정·팝업·공 다시 놓기마다 | ⚠ 작음 | 가끔이라 괜찮음. 자주 쓰면 미리 만들어 재사용 |
| `BallSpawner` 의 `new List<Ball>(prefabOf.Keys)` | 레벨 시작·클리어 때 | ✅ | 가끔 |
| `Physics.RaycastAll` (PinSpawner) | 핀 생성 때만 | ✅ | 가끔 |
| 문자열 합치기 `"Score : " + score`, `Debug.Log(...)` | 점수 바뀔 때, 생성 때 | ✅/⚠ | 점수 글자는 괜찮음. **`EffectPanelOpen` 의 `Debug.Log`** 는 효과마다 문자열 생성 → 확인 끝나면 지우기 |
| `rhthem` 소리 샘플 배열 | 매 프레임 | ✅ **잘 됨** | 배열을 미리 한 번 만들어 재사용 (`GetOutputData(samples)`), `MaterialPropertyBlock` 도 재사용 |
| `SongListUI` 버튼 람다 | 시작 때 1번 | ✅ | |
| `Ranking` JSON 읽기/쓰기 | 저장·랭킹 열 때 | ✅ | 10줄 제한이라 커지지 않음 |

## 6. 누수(Leak) 가능 지점
"누수" = 필요 없는데 계속 남아서 메모리를 차지하거나, 지워진 오브젝트를 계속 붙잡는 것.

| 위치 | 위험도 | 상황 | 지금 상태 |
|---|---|---|---|
| **`EffectPanelOpen.SpawnEffect`** 로 만든 파티클 | ⚠ 중간 | 효과 프리팹이 **스스로 지워지지 않는 프리팹**이면 판넬/버튼을 누를 때마다 씬에 쌓임 | JMO(CFXR) 효과는 `Clear Behavior: Destroy` 로 스스로 지워짐 → **다른 파티클을 넣을 땐 자동 삭제 설정 확인 필수** |
| `Pin.allPins` (static List) | ⚠ 낮음 | static 은 씬이 바뀌어도 남음 | `OnDisable` 에서 빠지므로 정상. 단, **Enter Play Mode Options 에서 Domain Reload 를 끄면** 이전 Play 의 값이 남을 수 있음 |
| `GameManager.Instance`, `SoundManager.instance` (static) | ⚠ 낮음 | 오브젝트가 지워져도 static 칸은 그대로 | Unity 의 `== null` 이 지워진 것도 null 로 봐서 재시작(씬 다시 불러오기)은 정상. Domain Reload 끄면 위와 같은 주의 |
| `BallSpawner` ↔ `Ball` 이벤트 | ✅ | 공에 구독을 걸고 해제는 안 함 | 공과 스포너가 같은 씬에서 같이 사라져 문제 없음 |
| `EffectButtonPress` 리스너 | ✅ | Awake 에서 추가, 해제 안 함 | 같은 오브젝트라 같이 사라짐 |
| `LevelManager`, `SongListUI` 이벤트 | ✅ | OnDestroy 에서 해제 | 잘 됨 |
| `Ball` 잡기/놓기 리스너 | ✅ **잘 됨** | OnEnable 추가 / OnDisable 해제 | 창고에서 재사용해도 중복 연결 없음 |
| 코루틴 | ✅ | 레벨 시작 때 `StopAllCoroutines`, 팝업은 `StopCoroutine` 후 재시작 | 겹쳐 도는 코루틴 없음 |
| `DontDestroyOnLoad` | ✅ 없음 | | 씬 재시작 때 매니저가 겹치지 않음 |

## 7. 한 줄 요약
- **잘 된 점**: 책임 나누기, 이벤트 연결/해제, 공 풀링, 프리팹 재사용 구조, 효과의 OnDisable 복구, rhthem 의 할당 없는 매 프레임 처리
- **아쉬운 점**: 큰 매니저(ButtonManager·LevelManager), 싱글톤 직접 의존(DIP), 효과·UI 릴레이·Bounds 계산의 반복, **Pin 의 매 물리 프레임 OverlapSphere 할당**, 효과 파티클 자동 삭제에 의존
